# 휴대폰 실기기 테스트 결과표

ROADMAP Task 022에서 iOS Safari와 Android Chrome으로 PRD §3 수용 기준, §5 화면 상태, 성능 목표를 확인하고 결과를 이 문서에 기록합니다. Task 020 통합 테스트(`tasks/020-integration-test.md`)는 데스크톱 Chromium으로 했으므로, 여기서는 **실제 카메라·실제 라벨·휴대폰 브라우저에서만 드러나는 동작**을 중심으로 봅니다.

결과 칸 표기: `통과` / `실패(내용)` / `해당 없음` / 비워 두면 미확인

## 2. 휴대폰에서 개발 PC에 접속하기 (HTTPS)

휴대폰 브라우저는 HTTPS(보안 컨텍스트)에서만 카메라를 허용합니다. 사내 서버가 준비되기 전에는 개발 PC에서 HTTPS로 띄워 접속합니다.

### 2-1. 개발 PC에서 HTTPS 서버 실행

```bash
# 1) 개발 PC의 사내 Wi-Fi IP 확인 (macOS)
ipconfig getifaddr en0          # 예: 192.168.0.23

# 2) 그 IP를 --hostname으로 주고 실행. 테스트 데이터는 실데이터와 분리한다
DATA_DIR=/tmp/duckil-device-test npx next dev --turbopack --experimental-https --hostname 192.168.0.23
```

- `--hostname`에 **IP를 직접** 줘야 합니다. Next.js는 `localhost`, `127.0.0.1`, `::1`과 `--hostname` 값으로만 인증서를 만듭니다. `npm run dev:https`처럼 `0.0.0.0`을 주면 인증서에 휴대폰이 접속할 IP가 없어 인증서 오류가 납니다
- IP가 바뀌면 기존 인증서가 그 IP에 맞지 않으므로, 다음 실행 때 Next.js가 인증서를 새로 만듭니다
- 인증서는 프로젝트의 `certificates/`(git 제외)에 생기고, 이 인증서를 발급한 개발용 루트 인증서(mkcert)는 `~/Library/Application Support/mkcert/rootCA.pem`에 있습니다
- 휴대폰과 개발 PC는 같은 Wi-Fi에 있어야 하고, macOS 방화벽이 켜져 있으면 node의 수신 연결을 허용합니다

### 2-2. 휴대폰에 개발용 루트 인증서 설치

> ⚠️ 휴대폰에는 `rootCA.pem`만 보냅니다. 같은 폴더의 `rootCA-key.pem`(개인키)은 절대 보내거나 공유하지 않습니다. 테스트가 끝나면 휴대폰에서 인증서를 지웁니다.

**iOS (Safari)**

1. `rootCA.pem`을 AirDrop이나 메일로 iPhone에 보냅니다
2. **설정 > 프로파일이 다운로드됨**(또는 설정 > 일반 > VPN 및 기기 관리)에서 설치합니다
3. **설정 > 일반 > 정보 > 인증서 신뢰 설정**에서 방금 설치한 mkcert 인증서를 켭니다 (이 단계를 빼먹으면 계속 인증서 오류가 납니다)
4. Safari에서 `https://192.168.0.23:3000` 접속 → 주소창에 경고가 없는지 확인

**Android (Chrome)**

1. `rootCA.pem`을 휴대폰으로 옮깁니다 (필요하면 확장자를 `.crt`로 바꿉니다)
2. **설정 > 보안 > 암호화 및 사용자 인증 정보 > 인증서 설치 > CA 인증서**에서 설치합니다 (메뉴 이름은 제조사마다 조금 다릅니다)
3. Chrome에서 `https://192.168.0.23:3000` 접속 → 경고가 없는지 확인

### 2-3. 사내 서버로 접속하는 경우

`docs/guides/deployment.md`대로 배포한 HTTPS 주소로 접속합니다. 공인 도메인 인증서면 휴대폰 설정이 필요 없고, 사내 CA 인증서면 2-2와 같은 방법으로 사내 루트 인증서를 설치합니다.

### 4-2. 내보내기 임계치 판단 (ROADMAP Q3)

- 200건 내보내기 시간·메모리가 서버에서 문제없으면 경고 200건 / 상한 500건을 유지합니다
- 시간이 `proxy_read_timeout`(120초)에 가깝거나 메모리가 `max_memory_restart`(1G)에 가까우면 `src/lib/constants.ts`의 `EXPORT_WARN_THRESHOLD`·`EXPORT_HARD_LIMIT`를 낮추고 이 표에 근거를 남깁니다

## 5. 실패·미달 항목 처리 규칙

1. 결과표의 비고에 재현 방법(기기, 화면, 순서)을 적습니다
2. 기능 결함은 바로 고칠 수 있으면 고치고 해당 항목을 다시 확인합니다
3. 성능 목표 미달이나 바로 고치기 어려운 항목은 `docs/ROADMAP.md`에 개선 Task를 추가하고(Phase 6 뒤, 번호 024부터), 이 문서 비고에 Task 번호를 적습니다
4. 기기·브라우저 한계로 해결할 수 없는 항목(예: iOS 진동)은 `해당 없음`과 이유를 적습니다
