## 개요

더미 화면으로 핵심 흐름(홈 → 스캔 → 정보 확인 → 사진 2장 → 저장 → 다음 스캔 → 상세 수정·삭제 → 내보내기)을 375x812, 390x844에서 끝까지 따라가며 부족한 점을 찾았다. 화면만 고치면 되는 항목은 Phase 2 코드에서 바로 고쳤고, API·데이터에 영향이 있는 항목은 PRD/ROADMAP에 반영했다. 이어서 Phase 2 완료 조건을 검증했다.

> 사용자가 자리에 없는 상태에서 진행했다. shrimp-rules §9-4(데이터 모델·API 계약 영향 시 사용자 확인)에 따라 **API 계약을 넓히지 않는 보수적인 기본값**만 골랐고, 모두 ROADMAP 확인 필요 사항(Q11~Q13)에 올려 두었다. 데이터 모델(PRD §6 `records` 컬럼)과 Zod 스키마, 타입은 바꾸지 않았다.

## 확인 필요

사용자 확인 없이 임시 기본값으로 정한 항목이다. 답변에 따라 ROADMAP의 해당 Task만 고치면 된다.

- **Q11 상세 화면 사진 삭제**: 지금은 교체만 가능하다. 잘못 찍은 사진을 지우고 싶다는 요구가 있으면 `PATCH`에 사진 삭제 필드(예: `remove_barcode_photo=1`)를 추가하고 상세 화면에 비우기 버튼을 되살린다(Task 011·018, `photo-slot`의 `onClear`만 넘기면 됨).
- **Q12 내보내기 건수 미리 표시**: 지금은 다운로드 시 1회만 확인한다. 기간을 고를 때 바로 "n건"을 보여주려면 Task 019에서 디바운스 후 `GET /api/records?from&to&limit=1`을 호출하면 된다(API 변경 없음).
- **Q13 검색·중복 대소문자 기준 차이**: 현장에서 혼동이 있으면 중복 판정도 대소문자 무시로 바꿀 수 있다(Task 009 `existsByProductLot`, Q9 변경).
- 새로 정한 문구: "스캔을 그만두시겠습니까?", "입력한 내용과 사진은 저장되지 않습니다", "그만두기", "계속 입력". PRD §5 스캔 표에 이탈 확인 행을 추가했다.

## 변경 사항 요약

- 화면만 고친 항목 4건(하단 고정 저장, 이탈 확인, 상세 비우기 제거, 재촬영 변경 추적), 문서로 결정한 항목 3건(Q11~Q13), 변경 없음 확인 5건.
- `AppHeader`에 `onBack`을 추가해 링크 대신 버튼으로 뒤로 가기를 처리할 수 있게 했다. 스캔 화면은 헤더까지 `ScanFlow`가 그린다.
- `PhotoSlot`의 `onClear`를 선택으로 바꿔, 넘기지 않으면 비우기 버튼이 사라지고 재촬영 버튼이 전체 폭이 된다.
- Phase 3에 영향: Task 011 `PATCH`는 사진 삭제를 받지 않음, Task 018은 `DetailSaveInput`(바뀐 필드 + 재촬영한 슬롯만)을 그대로 `FormData`로 전송. 데이터 모델·Zod 스키마·타입 변경은 없다.
- Phase 2 완료. 다음은 Phase 3 Task 009(SQLite 초기화 및 리포지토리).
